## Autres points contrôlés

- **Coffre réel `~/.bcc`** : absent avant (`ls: No such file or directory`) et absent après
  `pnpm run test`. `test/helpers/temp-vault.ts` est le seul point d'injection utilisé par
  `token-storage.test.ts`, sur `mkdtemp` de `os.tmpdir()`, nettoyé en `finally`. Aucun `.tmp`
  de coffre résiduel trouvé après exécution.
- **Jetons de test** : recherche ciblée sur les motifs de jeton plausibles (`figd_...`,
  `sk-...`, `ATATT...`) dans `test/` — toutes les valeurs trouvées portent un suffixe
  explicitement fictif (`"figd_jamais-sur-le-disque-888"`, `"ATATT3xFf-jeton-de-test-suffisamment-long"`,
  etc.), aucune ne ressemble à un jeton réel récupérable.
- **Stub `globalThis.fetch`** (`test/helpers/stub-fetch.ts`) : restauration vérifiée par
  sonde — même quand la fonction `run()` passée à `withStubbedFetch` lève (assertion en
  échec), le `finally` restaure `globalThis.fetch` à sa valeur d'origine. Chaque test
  Jira/Figma rappelle `withStubbedFetch` individuellement (pas de stub posé une fois pour
  tout un fichier), donc pas de fuite possible entre tests d'un même fichier ni entre
  fichiers (`node --test` exécute chaque fichier dans son propre contexte de module).
- **Hook d'alias** (`test/alias-hook.mjs`) : un import `@/lib/does-not-exist` produit
  `ERR_MODULE_NOT_FOUND` nommant le spécificateur fautif (`Cannot find package '@/lib'`),
  jamais un module silencieusement absent. Vérifié aussi : en présence d'homonymes
  `dup.ts`/`dup.js`, un import sans extension résout vers `.ts` (ordre de
  `IMPLICIT_EXTENSIONS`), conforme au commentaire du fichier.
- **Commentaire « limite documentée du module »** (`test/token-storage.test.ts:188-224`) :
  le test est explicitement présenté comme verrouillant « le comportement observé, pas un
  comportement souhaité », avec l'avertissement qu'il devra changer si le module change.
  Le comportement qu'il décrit (une lecture non pure peut montrer un graphe sans `Secret` à
  la garde puis un `Secret` au sérialiseur) correspond mot pour mot à l'invariant documenté
  en commentaire de `encryptDocument` dans `lib/token-storage.ts:517-525` (« INVARIANT, à
  charge d'`encode()` ... »). Cohérent, pas de garantie déguisée en observation.
- **Script `test` de `package.json`** : le motif est quoté (`'test/**/*.test.ts'`), donc non
  soumis à l'expansion de `sh` (confirmé : `sh -c 'echo test/**/*.test.ts'` ne développe pas
  le motif, `**` n'étant pas un globstar hors bash avec `shopt -s globstar`/zsh). Sonde
  positive : un fichier de test ajouté temporairement dans `test/helpers/__probe_subdir/` est
  découvert et exécuté par `pnpm run test`. Sonde d'échec : un test délibérément rouge fait
  sortir `pnpm run test` avec le code `1` (`[ELIFECYCLE] Test failed`). Les deux fichiers de
  sonde ont été supprimés après vérification (`git status --short` propre côté `test/`
  hormis le contenu livré).
- **Pas de dépendance ajoutée** : `package.json` ne diffère que par l'ajout du script `test`
  (`git diff -- package.json`), aucune entrée `devDependencies` nouvelle (pas de
  Jest/Vitest/Mocha), conforme au critère d'acceptation du ticket.
- **Portée du diff** : `git status --short` ne montre que `test/` (untracked) et
  `package.json` (modifié) ; `git diff --stat -- lib/ app/ docs/ tsconfig.json` est vide.
